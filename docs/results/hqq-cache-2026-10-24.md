# Native HQQ cache result

## Result

The selected native Transformers HQQ 8-bit `QuantizedCache` reduced measured persistent KV storage while keeping the measured mean teacher-forced metrics below the study's fixed limits on 256 held validation blocks. The study does not establish statistical equivalence or generated-text quality.

The main result on block IDs `[128,384)` was:

| Measure | HQQ8 result | Limit |
|---|---:|---:|
| Whole-block paired NLL increase, nats per token | 0.0006790659502 | 0.02 |
| Whole-block teacher KL, nats per position | 0.001834100909 | 0.02 |
| Decode paired NLL increase, nats per token | 0.001368910725 | 0.02 |
| Decode teacher KL, nats per position | 0.003668201817 | 0.02 |
| Whole-block teacher-forced argmax agreement | 98.4009% | Not gated |
| Decode teacher-forced argmax agreement | 96.8018% | Not gated |

The fixed gates apply to means. Positive NLL increases exceeded `0.02` on three of the 256 whole blocks and 21 of the 256 decode blocks. Absolute deltas exceeded `0.02` on four whole blocks and 31 decode blocks. The confirmatory whole-block deltas ranged from `-0.03838` to `0.03651`; decode deltas ranged from `-0.07737` to `0.07360`. No per-block preservation claim follows from the mean result.

## Validation and selection

The study compared the identity `DynamicCache`, native HQQ8, and native HQQ4 on the official WikiText-2 validation range `[0,128)`. Each candidate saw all 128 blocks in 32 batches of four. HQQ8 was selected and frozen before any confirmatory block was evaluated.

| Candidate | Whole NLL increase | Whole teacher KL | Decode NLL increase | Decode teacher KL | Whole argmax agreement | Decode argmax agreement | Mean gates | Length-128 storage, four-block batch |
|---|---:|---:|---:|---:|---:|---:|---|---:|
| Identity | 0 | 0 | 0 | 0 | 100% | 100% | Pass | 58,720,256 B |
| HQQ8 | -0.000537332599 | 0.001625399764 | -0.001083194287 | 0.003250799527 | 98.5718% | 97.1435% | Pass | 31,195,136 B |
| HQQ4 | 1.449557770 | 1.581062763 | 2.922124393 | 3.162125527 | 64.6973% | 29.3945% | Fail | 16,515,072 B |

HQQ4 used fewer bytes but failed all four quality gates by large margins. HQQ8 was the passing HQQ candidate and used fewer bytes than identity, so the fixed selection rule chose HQQ8.

Validation paired NLL deltas ranged from `0` to `0` for identity, `-0.02877` to `0.01682` whole-block and `-0.05799` to `0.03390` decode for HQQ8, and `0.38909` to `3.27487` whole-block and `0.78436` to `6.60173` decode for HQQ4.

## Persistent cache storage

The driver measured unique backing tensor storage for the complete batch, including native HQQ payload and metadata tensors. The values below are measured batch totals, not per-sequence extrapolations.

| Sequence length | Identity bytes | HQQ8 bytes | Reduction |
|---:|---:|---:|---:|
| 64 | 29,360,128 | 15,597,568 | 46.875% |
| 95 | 43,581,440 | 29,818,880 | 31.578947% |
| 96 | 44,040,192 | 23,396,352 | 46.875% |
| 97 | 44,498,944 | 23,855,104 | 46.3917526% |
| 127 | 58,261,504 | 37,617,664 | 35.4330709% |
| 128 | 58,720,256 | 31,195,136 | 46.875% |

Savings vary with sequence length because HQQ retains recent residual tokens before quantization. These cache tensor totals exclude model weights, temporary tensors, and allocator reserve. They are not whole-process or total-GPU-memory savings.

## Workload and reproducibility

The run used Qwen3-0.6B at revision `c1899de289a04d12100db370d81485cdf75e47ca`, WikiText-2 raw revision `b08601e04326c79dfdd32d625aee71d232d685c3`, context length 128, BF16, eager attention, and Transformers 5.20.2 with HQQ 0.2.8.post1. HQQ used key and value axes 1, group size 64, and residual length 32. The sequence used one 64-token prefill followed by 64 single-token cache updates per block.

The frozen validation set used IDs `[0,128)`. Confirmation used the separate held tail `[128,384)`, or 256 blocks in 64 batches. Every batch's block IDs were recorded before its first model forward. Identity, HQQ8, and HQQ4 validation rows, the frozen selection, confirmatory rows, and all attempt records are included in the [canonical receipt bundle](../evidence/hqq-cache-20261024/). The bundle uses LF line endings. Its manifest records each untouched source file's SHA-256 and source line ending alongside the canonical copy's SHA-256. The publication checker recomputes row summaries and selection using the study helpers.

The validation and confirmatory actions had 600-second and 1,200-second budgets. The driver required 10 GiB of free disk and capped allocated CUDA memory at 16 GiB at batch boundaries. The confirmatory action took 338.859 seconds. CUDA peak allocated memory was 1,443,333,120 bytes and peak reserved memory was 1,543,503,872 bytes on an NVIDIA GeForce RTX 5080 Laptop GPU. Process RSS was not measured. These are run-resource observations, not performance or throughput measurements.

To check the published receipts without loading HQQ or using a GPU, run:

```powershell
python tools/check_hqq_receipts.py
```

The existing CPU test and verification workflow also runs the receipt check. The checker reconstructs original CRLF receipt bytes in a unique temporary directory and verifies their raw hashes before recomputing row summaries and the selection decision. Frozen hash fields and the historical absolute validation path remain unchanged; checking never follows that path. The original frozen selection SHA-256 is `600632d7e8603596e8dd01629fd8f6db0c8a7a636ca7ef923661cccdb7d0b7fb`. Current source binding permits only Git's LF/CRLF conversion. The study source recorded in the original receipts has SHA-256 `d1de0653556906827fc5753bbc0f4a792ca29e3680eab81d3251ada7b8c4ec17` for `tools/quantized_metrics.py`. The unchanged raw run data remains under ignored `evidence/hqq-b4-*` directories.

## Scope and credit

This experiment measures one pinned model, corpus, dtype, context, schedule, and set of validation blocks. It reports no throughput, generated-text quality, whole-process memory reduction, training improvement, or new quantizer design. Transformers supplies the native cache interface and HQQ supplies the quantization backend. The earlier cache-sharing and distillation study remains separate; its candidates failed their quality gate and its selected identity cache saved no KV bytes.
